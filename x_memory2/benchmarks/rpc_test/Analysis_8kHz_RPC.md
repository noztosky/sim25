# 8kHz RPC Latency Benchmark Analysis (10s Average)

본 문서는 초고해상도 제어 주기인 8kHz(125us 주기) 환경에서 RPC 방식의 통신 지연 특성을 분석한 결과입니다. 본 실험을 통해 RPC가 고속 드론 제어나 정밀 시뮬레이션에 부적합함이 최종적으로 입증되었습니다.

## 1. 실험 요약
- **Target IMU Hz**: 8,000 Hz (125us)
- **Target PWM Hz**: 400 Hz (2.5ms)
- **Measured IMU Hz**: 5,507 Hz (유효 샘플링 성능 약 **68.8%**)
- **Measured PWM Hz**: 398 Hz (안정적)
- **Real-Time Factor (RTF)**: 0.99

## 3. 분석 결과 및 시사점

### 3.1 물리적 처리 한계(Throughput Ceiling) 도달
- 8kHz 목표 달성을 위해서는 초당 8,000번의 데이터 교환이 필요하나, 실제 측정치는 5,507Hz에 머물러 있음.
- 이는 현재 시스템 환경에서 RPC(TCP/IP stack + Serialization)가 제공할 수 있는 **물리적 대역폭의 한계(약 5.5kHz~6kHz)**에 도달했음을 의미함.

### 3.2 결정성(Determinism)의 완전한 상실
- 히스토그램 데이터를 보면, 전체 샘플의 **절반 이상(55.25%)이 설계 주기를 30% 이상 초과하는 심각한 지연**을 보이고 있음.
- 정상 범위([0])에 들어오는 샘플은 단 **9.1%**에 불과함. 이는 비행 제어 알고리즘 입장에서 수신되는 데이터의 90%가 '이미 과거의 데이터'이거나 '비규칙적인 타이밍'으로 들어오고 있음을 뜻하며, 실제 비행 시 통제 불능 상태를 유발함.

### 3.3 주파수 증가에 따른 성능 상관관계
- 1kHz(99% Stable) -> 4kHz(92% Stable) -> 8kHz(**9% Stable**)로 이어지는 급격한 성능 저하 곡선은, 통신 방식의 '고정 지연 시간'이 고주파수 제어의 '짧은 데드라인'을 충족하지 못해 발생하는 병목 현상을 완벽하게 증명함.

## 4. 최종 결론
- 8kHz SIL 시뮬레이션에서 RPC 방식은 사용이 불가능한 수준의 샘플 누락과 지터를 발생시킴.
- 마이크로초(us) 단위의 정밀 제어를 실현하기 위해서는 커널 및 네트워크 스택을 우회하는 **Zero-copy 기반의 SHM(공유 메모리) 아키텍처 도입이 유일한 해결책**임.
