# 4kHz RPC latency Benchmark Analysis (10s Average)

본 문서는 4kHz(250us 주기) 환경에서 RPC 방식의 통신 지연 특성을 분석한 결과입니다. 10초간의 누적 데이터를 바탕으로 작성되었습니다.

## 1. 실험 요약
- **Target IMU Hz**: 4,000 Hz (250us)
- **Target PWM Hz**: 400 Hz (2,500us)
- **Measured IMU Hz**: 3,347 Hz (유효 샘플링 성능 약 83.7%)
- **Measured PWM Hz**: 395 Hz (안정적)
- **Real-Time Factor (RTF)**: 0.99

## 3. 분석 결과 및 시사점

### 3.1 RPC의 물리적 한계 노출
- IMU 목표 주파수인 4kHz를 달성하기 위해 10초간 40,000번의 데이터를 요청해야 하지만, 실제로는 33,471번에 그침.
- 이는 RPC 통신에 수반되는 오버헤드가 누적되어 초당 약 650개의 샘플을 물리적으로 수신하지 못하고 있음을 의미함.

### 3.2 비결정적 지연(Non-deterministic Jitter)
- 전체 샘플의 약 **8%**가 5% 이상의 지터를 겪고 있음.
- 특히 **1.7% (571회)**의 샘플은 30% 이상의 심각한 지연을 보임. 이는 고속 드론 제어를 위한 SIL(Software-In-the-Loop) 시뮬레이션에서 제어 루프의 결정성을 파괴하는 핵심 요인임.

### 3.3 결론
- RPC 방식은 400Hz 수준의 PWM 전송에는 매우 안정적(100% Stable)이나, **4kHz 이상의 고속 센서 데이터 수집에는 부적합**함이 증명됨.
- 고속 제어 주기를 완벽하게 수용하기 위해서는 지연율을 1% 미만으로 억제할 수 있는 **SHM(공유 메모리) 방식의 도입이 필수적**임.
